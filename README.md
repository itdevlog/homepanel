# Home Panel

Домашняя панель: **кто дома** — по подключённым к WiFi клиентам роутера OpenWrt,
с историей присутствия и статистикой.

## Состав

- `server/` — сервер на Python 3 (только стандартная библиотека) + SQLite и
  ванильная веб-панель (без сборки).
- `router/` — агент для роутера OpenWrt (ucode + procd) и страница настроек
  LuCI; см. `docs/superpowers/plans/2026-10-18-homepanel-router.md`.
- `docs/superpowers/` — спецификация и планы реализации.

Архитектура: агент на роутере периодически снимает список ассоциированных
WiFi-клиентов и отправляет снимок на сервер (`POST /api/ingest`); сервер хранит
устройства, события и агрегаты, а панель показывает состояние и историю.

## Возможности панели

- **Кто дома** — карточки людей, сводка (люди/устройства дома, состояние
  роутера), блок «Инфраструктура» по комнатам (сколько ламп и техники онлайн),
  предупреждения, аномалии («обычно в это время дома») и быстрые действия для
  неопознанных устройств.
- **Устройства** — поиск, фильтры, сортировка, правка имени/человека,
  роли (человек / инфраструктура / гость), типа и комнаты, заметки, массовые
  действия, удаление («забыть устройство»), объединение дублей MAC,
  мини-график присутствия за сутки и экспорт в CSV.
- **История** — события приходов/уходов с поиском и фильтрами, часы онлайн по
  дням и неделям.
- **Аналитика** — тепловая карта «дом за неделю», приходы/уходы по часам,
  распределение устройств по людям, новые устройства, таймлайн дня человека,
  график сигнала WiFi, календарь месяца и сравнение недель.
- **Настройки** — уведомления в браузере, правила авто-разметки устройств,
  резервная копия разметки (экспорт/импорт JSON).
- **Поиск** — глобальный поиск по устройствам и событиям (`Ctrl+K`).
- **Тема и PWA** — авто/тёмная/светлая, установка на телефон, нижнее меню и
  офлайн-оболочка.

## Требования

- Python 3.11+ (только стандартная библиотека, внешних зависимостей нет).
- Любая ОС для разработки; для эксплуатации — Debian.

## Установка сервера

Полный пошаговый гайд (VPS, DNS, systemd, Nginx Proxy Manager, TLS, роутер):
[`docs/deploy.md`](docs/deploy.md).

1. Скопировать репозиторий на сервер.
2. Создать конфигурацию из примера и задать секрет. Файл должен читаться
   пользователем сервиса (`root:homepanel`, режим `0640`):

   ```bash
   install -Dm640 -o root -g homepanel \
     server/config.json.example /etc/homepanel/config.json
   "$EDITOR" /etc/homepanel/config.json
   ```

   Поля `config.json`:

   | Поле | Назначение | По умолчанию |
   |---|---|---|
   | `host` | адрес прослушивания (`127.0.0.1` — только за прокси; LAN-адрес или `0.0.0.0` — для прямых запросов агента) | `127.0.0.1` |
   | `port` | порт | `8787` |
   | `secret` | общий секрет с агентом (`X-Homepanel-Key`) | `CHANGE_ME` |
   | `graceSeconds` | окно дребезга присутствия, с | `300` |
   | `retention.minuteDays` | срок хранения минутных данных, дней | `30` |
   | `retention.dailyDays` | срок хранения дневных данных, дней | `365` |
   | `retention.signalDays` | срок хранения истории сигнала WiFi, дней | `7` |
   | `backup.dir` | каталог ежедневных копий разметки | `<рядом с dbPath>/backups` |
   | `backup.keep` | сколько ежедневных копий хранить | `7` |
   | `backup.hour` | час суток, после которого делается копия (0–23) | `3` |
   | `guestToken` | токен гостевой ссылки `?guest=…` (только чтение); пусто — выключено | `""` |
   | `apNames` | имена точек доступа: объект «BSS → имя» | `{}` |

   Гостевая ссылка: задайте `guestToken` и откройте `https://…/?guest=ТОКЕН`.
   Панель покажет данные без кнопок изменения. Это режим просмотра, а не
   полноценная авторизация: запросы без токена по-прежнему имеют полный доступ.
   | `publicUrl` | публичный адрес панели | `""` |
   | `dbPath` | путь к файлу SQLite | `data/homepanel.sqlite3` |
   | `staticDir` | каталог статики панели | `<пакет>/../static` |

   Имена точек, например:
   `"apNames": {"phy0-ap0": "FREE", "phy0-ap1": "FREE1", "phy1-ap0": "FREE-5HZ"}`.

3. Запустить:

   ```bash
   python3 server/server.py --config /etc/homepanel/config.json
   ```

### systemd

Юнит — `server/systemd/homepanel.service` (ожидает пользователя `homepanel` и
репозиторий в `/home/homepanel/homepanel`; пути и `User=` при необходимости
поправить). Создание пользователя, каталог для базы и права на конфиг —
`docs/deploy.md`, §2–3.

```bash
sudo install -Dm644 server/systemd/homepanel.service /etc/systemd/system/homepanel.service
sudo systemctl daemon-reload
sudo systemctl enable --now homepanel
```

### За Nginx Proxy Manager

Панель и API рассчитаны на работу за обратным прокси с TLS:

- прокси-хост → `http://127.0.0.1:8787`;
- включить SSL (Let's Encrypt);
- внешний доступ ограничивать на стороне NPM (allowlist/фаервол) —
  приложение авторизации не имеет и рассчитано на локальную сеть;
- открывать панель по HTTPS-домену (не по `IP:порт`), иначе браузерные
  уведомления не работают.

`/api/ingest` должен быть доступен агенту роутера. Два варианта:

- **Через NPM (рекомендуется).** В настройках агента `server_url` =
  публичный HTTPS-адрес панели (`https://homepanel.example.com/api/ingest`),
  а `host` сервера остаётся `127.0.0.1`. На стороне NPM разрешите доступ к
  `/api/ingest` с IP роутера.
- **Напрямую по локальной сети.** `server_url` =
  `http://<LAN-IP-сервера>:8787/api/ingest`, а `host` сервера выставьте в
  LAN-адрес (например `192.168.1.10`) или `0.0.0.0`. Порт `8787` при этом
  должен быть доступен только из локальной сети.

При `host = 127.0.0.1` и `server_url` с прямым `IP:8787` агент получит
`connection refused`.

## Роутер (OpenWrt)

Агент `homepanel-agent` (ucode + procd) снимает список WiFi-клиентов со всех
точек доступа (`ubus call hostapd.* get_clients`), добавляет проводных
клиентов из bridge FDB и ARP, обогащает арендами DHCP и отправляет снимок на
сервер. Вместе с клиентами уходят счётчики трафика WiFi, здоровье роутера
(uptime, load, память, WAN) и подтверждения команд управления.

Отдельный сервис `homepanel-events` слушает `ubus listen hostapd.*` и при
подключении/отключении клиента сразу запускает отправку — присутствие
обновляется за секунды, а не за интервал опроса. Если watcher недоступен,
агент продолжает работать по таймеру (по умолчанию 20 с).

Сервер может попросить агента:

- **поставить на паузу** интернет для MAC (forward-трафик блокируется
  nftables, LAN и панель остаются доступны);
- **отключить** WiFi-клиента (`hostapd del_client`);
- **перезапустить** агент.

Настройки и статус — в LuCI на странице *Services → Home Panel*.

### Установка

Одной командой (на роутере, от root):

```sh
wget -O /tmp/hp.sh \
  https://raw.githubusercontent.com/itdevlog/homepanel/main/router/bootstrap.sh \
  && sh /tmp/hp.sh
```

Загрузчик проверяет окружение (OpenWrt, DNS, место в `/overlay`, наличие
`wget`/`uclient-fetch`), скачивает архив репозитория, при необходимости
доставляет недостающие ucode-модули (`ucode-mod-fs`, `-uci`, `-ubus`,
`-uloop`) и запускает `router/install.sh`. Повторный запуск — это обновление:
`/etc/config/homepanel` сохраняется. Флаги: `--ref REF` (ветка/тег),
`--dry-run`, `--dest DIR`, `--no-deps`, `--archive PATH`.

> В busybox ash нет process substitution, поэтому форма
> `sh <(wget -O - URL)` из инструкций podkop на OpenWrt не работает.
> Используйте команду выше либо `wget -qO- URL | sh`.

#### Вручную

1. Скопировать каталог `router/` на роутер:

   ```bash
   scp -r router root@192.168.1.1:/tmp/
   ```

2. Запустить установщик:

   ```bash
   ssh root@192.168.1.1 'sh /tmp/router/install.sh'
   ```

   Установщик раскладывает файлы из `router/files/` в `/`, выставляет права,
   включает и запускает сервис и сбрасывает кэш LuCI. Существующий
   `/etc/config/homepanel` при этом сохраняется — повторная установка не
   затирает `server_url` и `secret`. Флаг `--dry-run` раскладывает файлы, но
   не включает и не запускает сервис (нужен для тестов и ручной выкладки),
   `--dest DIR` меняет корень установки.

3. В LuCI *Services → Home Panel* заполнить:
   - `server_url` — адрес `POST /api/ingest` (см. раздел выше);
   - `secret` — тот же секрет, что в `config.json` сервера;
   - `interval` — период опроса, с (по умолчанию 20);
   - `wired` — показывать проводных клиентов (bridge FDB + ARP);
   - `control` — разрешить серверу паузу, kick и перезапуск агента;
   - `events` — мгновенная отправка по событиям hostapd.

   Блок «Статус агента» показывает время последней отправки, число клиентов
   в снимке, версию, состояние наблюдателя событий, доступность nftables и
   текст последней ошибки; кнопка «Отправить сейчас» отправляет снимок
   немедленно.

4. Проверка из SSH: `ubus call homepanel status`, `ubus call homepanel send`.

### Персистентность

При обновлении прошивки (`sysupgrade`) разделы `/usr`, `/www` и
добавленный вручную init-скрипт не сохраняются. Поэтому установщик:

- кладёт копию всех файлов в `/etc/homepanel/` (`/etc` переживает
  `sysupgrade`);
- регистрирует сохраняемые пути в `/lib/upgrade/keep.d/homepanel`
  (`/etc/config/homepanel`, `/etc/homepanel`, `/etc/init.d/homepanel-agent`,
  `/etc/init.d/homepanel-events`).

Переустановка после `sysupgrade`:

```bash
ssh root@192.168.1.1 'sh /etc/homepanel/install.sh'
```

Пользовательский конфиг при этом не перезаписывается, поэтому донастройка в
LuCI не требуется.

### Ручной чек-лист

Базовые шаги:

- [ ] Сервисы запущены: `/etc/init.d/homepanel-agent status` и
      `/etc/init.d/homepanel-events status`.
- [ ] В LuCI на странице *Home Panel* статус «Настроен», ошибок нет,
      «Наблюдатель событий» — работает, «nftables» — доступен.
- [ ] «Отправить сейчас» завершается успешно, время последней отправки
      обновляется.
- [ ] На сервере (`/api/state`) появляются устройства роутера.
- [ ] После `reboot` роутера оба сервиса стартуют автоматически.

Полная проверка router-v2 (проводные клиенты, трафик, пауза, kick,
перезапуск, задержка событий): [`docs/router-v2-checklist.md`](docs/router-v2-checklist.md).

## API router-v2

- `GET /api/state` — к устройствам добавлены `link` (`wifi`/`wired`),
  `paused`, `rx_bytes`, `tx_bytes`, `traffic_source` (`nlbw`/`wifi`/`none`),
  `role` (`person`/`infra`/`guest`/`unknown`), `kind` (угадывается по
  hostname: лампа/ТВ/телефон/ноутбук), `icon`, `room` и `merged`
  (MAC, вошедшие в устройство); появились блоки `router` (онлайн, uptime,
  load, память, WAN), `commands` (последние 10 команд), `infra`
  (`[{room, online, total}]` — сводка по комнатам для устройств с ролью
  «инфраструктура») и общий `traffic_source`.
- `GET /api/router/history?days=7|30` — история нагрузки и памяти роутера
  (7 дней по часам, 30 — по дням).
- `GET /api/traffic?mac=…&hours=24` — 5-минутные дельты трафика клиента и
  `source` (`nlbw`/`wifi`); проводные клиенты видны при работающем nlbwmon.
- `POST /api/control/pause` `{ "mac": "…", "paused": true }` — пауза
  интернета для клиента.
- `POST /api/control/kick` `{ "mac": "…" }` — отключить WiFi-клиента.
- `POST /api/control/restart` — перезапустить агент на роутере.

Агент 2.1 (флаг `nlbw` в UCI/JSON) раз в минуту читает
`nlbw -c json -g mac -n` и добавляет в снимок необязательный блок `nlbw` с
абсолютными счётчиками. Сервер считает 5-минутные дельты, поэтому трафик
показывается и для проводных клиентов; без nlbwmon используется iwinfo
(только WiFi). В панели: «Аналитика» → «Трафик устройств» (топ-5 и история
за 6/24/72 часа), в «Устройствах» — «за 5 мин» и спарклайн.

`apNames` в `config.json` — только начальные значения: имена точек
редактируются в «Настройки → Точки доступа». Комнаты, типы устройств и
иконки редактируются в «Настройки → Справочники».

## Безопасность

- Секрет `X-Homepanel-Key` защищает приём снимков; без него запросы к
  `/api/ingest` отклоняются с `401`.
- Панель аутентификации не имеет: не выставляйте её в интернет без
  ограничения доступа на стороне прокси/фаервола.
- Управление (пауза, kick, перезапуск агента) доступно любому, кто может
  отправить POST в API панели. Гостевая ссылка `?guest=…` запрещает только
  не-GET запросы и не является границей безопасности — не давайте её тем,
  кому нельзя доверять управление.
- Пауза блокирует только forward-трафик клиента: доступ к самому роутеру,
  DHCP и DNS в LAN сохраняется.

## Тесты

```bash
python3 -m unittest discover -s server/tests -t server   # сервер
node --test server/tests/js/                             # панель (чистая логика)
sh router/tests/run.sh          # агент: сбор снимка (WiFi, wired, router)
sh router/tests/run-send.sh     # агент: отправка на сервер
sh router/tests/run-control.sh  # агент: пауза, kick, acks
sh router/tests/run-events.sh   # watcher: debounce и rate-limit
sh router/tests/run-ubus.sh     # агент: ubus-объект (полностью — на роутере)
sh router/tests/run-luci.sh     # приложение LuCI (структура и JSON)
sh router/tests/run-install.sh  # установщик
sh router/tests/run-bootstrap.sh # загрузчик (локальный архив, без сети)
```

Тесты роутерной части требуют `ucode` (есть на OpenWrt; сборка из
`https://github.com/jow-/ucode`). Полная проверка ubus-объекта и страницы
LuCI выполняется на самом роутере.
