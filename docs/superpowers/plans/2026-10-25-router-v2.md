# Router v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add instant hostapd-driven presence, wired clients, per-client WiFi traffic, router health and remote control (kick / pause internet / restart agent) to Home Panel.

**Architecture:** The existing push agent stays the single transport. The server answers every `POST /api/ingest` with the desired pause list and one-shot commands; the agent applies them and acknowledges in the next snapshot. A small `homepanel-events` service listens to `ubus listen hostapd.*` and triggers an immediate send with a debounce. The server owns state in SQLite and exposes it through `/api/state` and new read/control endpoints.

**Tech Stack:** Python 3 stdlib + SQLite (server), vanilla ES modules (panel), ucode + procd + ubus/nftables (OpenWrt agent), shell tests.

**Spec:** `docs/superpowers/specs/2026-10-25-router-v2-design.md`

## Global Constraints

- Python 3 standard library only; no new server dependencies.
- Panel stays vanilla HTML/CSS/JS with no build step.
- Ingest schema 1 must keep working unchanged; schema 2 is additive.
- The agent payload keeps its existing `agent: {hostname, version, ts}` object (not flat fields).
- Commands are at-most-once: a command is executed by the agent at most one time, even if a response is lost.
- Server is the source of truth for pause state; the agent reapplies it after reboot.
- Guest token requests are read-only: every control POST must return 403 for guests.
- v1 has no admin authentication. Anyone with access to the panel (without guest token) can control clients; this is documented, not fixed here.
- All user-visible strings are Russian, matching the current UI.
- OpenWrt/busybox compatible; nftables, iwinfo and bridge tools are optional at runtime and must degrade gracefully.
- Tests must stay green after every task: `python3 -m unittest discover -s server/tests -t server`, `node --test server/tests/js/`, `sh router/tests/run.sh`.

## Review Focus

- A truncated or partial ingest (no `link`, no byte counters, no `router`) must not break presence updates or return 500; the old snapshot shape must remain accepted. Covered by Task 1 and Task 5 tests.
- A router without nftables, iwinfo or a writable ubus must not crash-loop the agent; failures become `acks` errors and the next snapshot still succeeds. Covered by Task 8.
- Duplicate or expired command acknowledgements must not double-execute a kick/restart or resurrect an expired command. Covered by Task 3 tests.
- The first traffic sample after agent restart, and a counter reset (`new < old`), must not produce a giant or negative spike. Covered by Task 4 tests.
- Guest mode must never reach a control endpoint. Covered by Task 6 test.

```sql
CREATE TABLE IF NOT EXISTS device_control (
    mac        TEXT PRIMARY KEY,
    paused     INTEGER NOT NULL DEFAULT 0,
    updated_at INTEGER
);
CREATE TABLE IF NOT EXISTS agent_commands (
    id      INTEGER PRIMARY KEY AUTOINCREMENT,
    ts      INTEGER NOT NULL,
    type    TEXT NOT NULL,
    mac     TEXT,
    status  TEXT NOT NULL DEFAULT 'pending',
    sent_ts INTEGER,
    ack_ts  INTEGER,
    error   TEXT
);
```

- `set_control` upsert, `paused=1/0`, always updates `updated_at`.
- `create_command`: if an active (`pending`/`sent`) command with same `type` and `mac` exists, return it; otherwise insert.
- `pending_commands`: select `status='pending'` ordered by id, limit clamped 1..20.
- `mark_commands_sent`: set `status='sent'`, `sent_ts=?` for the given ids that are still `pending`.
- `apply_acks`: for each ack, update only rows with `status IN ('pending','sent')` to `done` (ok) or `error` (not ok), set `ack_ts`.
- `expire_commands(now)`: update `pending`/`sent` rows older than TTL (kick 60 s, restart 90 s, chosen by `type`) to `error='timeout'`.
- `recent_commands(limit)`: newest first, clamped 1..50.
- `prune_commands(before_ts)`: delete `done`/`error` older than the cutoff.

```sql
CREATE TABLE IF NOT EXISTS router_samples (
    ts INTEGER PRIMARY KEY, uptime INTEGER, load1 REAL, load5 REAL, load15 REAL,
    mem_total INTEGER, mem_free INTEGER, wan_up INTEGER, wan_ip TEXT
);
CREATE TABLE IF NOT EXISTS device_traffic (
    mac TEXT PRIMARY KEY, rx_bytes INTEGER, tx_bytes INTEGER, ts INTEGER
);
CREATE TABLE IF NOT EXISTS traffic_samples (
    mac TEXT NOT NULL, bucket_ts INTEGER NOT NULL,
    rx_bytes INTEGER NOT NULL DEFAULT 0, tx_bytes INTEGER NOT NULL DEFAULT 0,
    PRIMARY KEY (mac, bucket_ts)
);
CREATE INDEX IF NOT EXISTS idx_traffic_ts ON traffic_samples(bucket_ts);
```

- `record_router`: ignore if the newest sample is younger than 20 s; insert otherwise.
- `router_latest`: newest row; `wan_up` is a bool.
- `router_series(from_ts, to_ts, group)`: `group == "hour"` → `strftime('%Y-%m-%dT%H', ts, 'unixepoch', 'localtime')`; `"day"` → `%Y-%m-%d`; aggregate with `AVG(load1)` and `(mem_total-mem_free)` as `mem_used`; return `{ts: bucket, load1, mem_used, wan_up}` where `wan_up` is `MAX(wan_up)`.
- `record_traffic(now, samples)`: for each `(mac, rx, tx)` with non-null bytes, read the previous `device_traffic` row; `delta_rx = 0` if no previous, else `rx - prev` if `rx >= prev` else `rx`; same for tx; upsert `device_traffic` with the absolute values and `ts=now`; insert-or-add into `traffic_samples` at `bucket_ts = now // 300 * 300`.
- `traffic_series`: rows in range ordered by bucket; `last_traffic` returns `{mac: {rx_bytes, tx_bytes, ts}}`.
- `prune_*`: delete rows older than cutoff.
