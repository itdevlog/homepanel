# Дизайн: Home Panel — присутствие по WiFi (OpenWrt + сервер)

- Дата: 2026-10-18
- Статус: утверждён, готов к планированию реализации
- Платформа роутера: Cudy WR3000S v1 — MediaTek MT7981BA (Filogic 820),
  2×Cortex-A53 @1.3 ГГц, 128 МБ flash (NAND), 256 МБ RAM, Wi-Fi 6,
  OpenWrt 25.12.4 (вариант «OpenWrt U-Boot layout»), ядро 6.12
- Платформа сервера: Debian, Python 3 (только стандартная библиотека)

## 1. Цель

Домашняя панель, которая показывает **кто дома**, определяя присутствие по
подключённым к WiFi клиентам роутера OpenWrt, и ведёт **историю/статистику**
присутствия. Управление в v1 — разметка устройств (имена, человек, тип,
свой/гость, скрытие).

Ключевые сценарии:

1. Открыть панель и сразу видеть, кто из людей дома, с какого времени, по
   какому устройству, на каком диапазоне/точке доступа.
2. Увидеть неопознанные устройства и разметить их (имя, человек, тип).
3. Посмотреть историю: сколько часов человек был онлайн по дням/неделям.
4. Получить веб-уведомление «пришёл/ушёл» (пока вкладка открыта).

## 2. Границы

### В рамках
- **Агент на роутере** (ucode + procd): периодически снимает список
  ассоциированных WiFi-клиентов со всех BSS и отправляет снимок на сервер.
- **Приложение LuCI** на роутере: страница настроек (адрес сервера,
  интервал, секрет, вкл/выкл, «отправить сейчас», статус).
- **Сервер** (Python 3 stdlib): приём снимков + JSON-API + хранение истории.
- **Веб-панель** (ванильный HTML/CSS/JS без сборки): живая доска «кто дома»,
  разметка устройств, графики истории, веб-уведомления.
- **SQLite** (`sqlite3` из stdlib) для устройств, событий и агрегатов.
- Деплой: systemd-юнит сервера; установочный скрипт для роутера.

### Вне рамок (YAGNI)
- Доступ из интернета силами приложения: внешний доступ ограничивается
  Nginx Proxy Manager / фаерволом (сторона пользователя). TLS завершает NPM.
- Авторизация/пользователи/сессии в панели (доступ локальный, без логина).
- Web Push при закрытой вкладке (service worker, VAPID) — будущая итерация.
- SSE/WebSocket — будущая итерация (в v1 живое обновление через polling).
- Блокировка/отключение устройств от WiFi, управление роутером — будущее.
- Мониторинг сервера (CPU/RAM/диск) и управление сервисами — отдельная тема.
- Упаковка роутерной части в `.apk` — будущая итерация.
- Карта, геолокация, мобильное приложение.

## 3. Архитектура

Поток данных:

```
OpenWrt: homepanel-agent (ucode, procd)
    └── каждые N сек: ubus get_clients по всем BSS + /tmp/dhcp.leases
    └── POST /api/ingest (X-Homepanel-Key)  ──HTTP──▶  homepanel-server
                                                          ├── SQLite (устройства, события, агрегаты)
                                                          └── JSON API /api/*
                                                               ▲
Внешний мир ──HTTPS──▶ Nginx Proxy Manager ──HTTP──▶ сервер ──┘  Браузер (панель)
```

Сервер — единственный, кто хранит состояние и историю; панель общается только
с ним. Агент только отправляет снимки (push) — серверу **не нужны SSH-ключи и
учётные данные роутера**.

### Компоненты

1. **`homepanel-agent`** (роутер, ucode + procd).
2. **Приложение LuCI `homepanel`** (роутер).
3. **`homepanel-server`** (сервер, Python 3 stdlib).
4. **Панель** (статика на сервере).
5. **Хранилище** (SQLite + `config.json`).

## 4. Данные с роутера

Открытые (проверено на целевой прошивке) объекты ubus:
`hostapd`, `hostapd-auth`, `hostapd.phy0-ap0`, `hostapd.phy0-ap1`,
`hostapd.phy1-ap0`, `iwinfo`.

Целевой роутер имеет три BSS: `phy0-ap0` (`FREE`, 2.4 ГГц),
`phy0-ap1` (`FREE1`, 2.4 ГГц), `phy1-ap0` (`FREE-5HZ`, 5 ГГц). Клиент может
быть ассоциирован с любой из них → агент опрашивает **все** и объединяет.

Способы получения клиентов:
- `ubus call hostapd.<bss> get_clients` → `{ "freq": ..., "clients": { "<mac>": {...} } }`
  (основной способ; точная форма полей проверяется живым примером на этапе реализации).
- `ubus call iwinfo assoclist '{"device":"<bss>"}'` (резервный способ).

Список BSS агент получает динамически: `ubus list 'hostapd.*'`, отбрасывая
служебные объекты `hostapd` и `hostapd-auth`.

Обогащение данными DHCP: `/tmp/dhcp.leases`, формат строки
`<expiry> <mac> <ip> <hostname> <clientid>` → карта `mac → (ip, hostname)`.

## 5. Контракт агент ↔ сервер

`POST /api/ingest`

Заголовки: `Content-Type: application/json`, `X-Homepanel-Key: <secret>`.

Тело:

```jsonc
{
  "schema": 1,
  "agent": { "hostname": "OpenWrt", "version": "1.0", "ts": 1760000000 },
  "clients": [
    { "mac": "aa:bb:cc:dd:ee:ff", "bss": "phy0-ap0", "band": "2.4",
      "signal": -52, "ip": "192.168.1.42",
      "hostname": "iPhone-Ivan", "connected_at": 1760000000 }
  ]
}
```

Семантика: `clients` — **полный** список ассоциированных сейчас клиентов.
Отсутствие MAC в снимке означает «не подключён» (сервер применяет grace).

Ответы: `200 {"ok": true, "ts": ...}`; `401` при неверном секрете (и `400`
при некорректном теле). Максимальный `schema` в v1 — `1`.

## 6. Агент (`homepanel-agent`)

- Язык: **ucode** (модули `ubus`, `uci`, `uloop`, `fs`). Запуск под **procd**
  через `/etc/init.d/homepanel-agent`.
- Конфиг — UCI `/etc/config/homepanel` (см. §13).
- Цикл (интервал по умолчанию 30 с):
  1. `ubus list 'hostapd.*'` → список BSS.
  2. По каждому BSS: `get_clients`; объединить клиентов (по MAC; при
     дублировании между BSS — «сильнейший» сигнал).
  3. Прочитать `/tmp/dhcp.leases`; обогатить `ip`/`hostname`.
  4. Сформировать снимок (§5) и отправить POST.
  5. Обновить состояние ubus-объекта `homepanel` (время последней отправки,
     число клиентов, результат) и записать ошибку в syslog при сбое.
- Идемпотентность: снимок заменяет состояние; очередь не копится, при
  недоступности сервера просто повтор на следующем тике.
- HTTP-отправка: busybox `wget` (`--post-file` + `--header`); резерв —
  `uclient-fetch`. Тело заранее пишется в `/tmp/homepanel.json`.
- **Режим `--once`** (dry-run): собрать снимок и напечатать в stdout, не
  отправляя — для отладки и офлайн-тестов.
- **ubus-объект `homepanel`** регистрируется агентом с методами:
  - `status` → JSON (последняя отправка, число клиентов, версия, ошибки);
  - `send` → немедленно выполнить один цикл отправки.
  Это позволяет странице настроек LuCI показывать статус и дёргать отправку
  без отдельного backend-скрипта.

## 7. Приложение LuCI (`homepanel`)

Ставится раскладкой файлов (без buildroot):

- `/usr/share/luci/menu.d/luci-app-homepanel.json` — пункт меню
  (напр. *Services → Home Panel*), `action.type = view`,
  `path = homepanel/overview`, зависит от ACL `luci-app-homepanel`.
- `/usr/share/rpcd/acl.d/luci-app-homepanel.json` — доступ: чтение/запись
  UCI-конфига `homepanel`; вызов ubus-объекта `homepanel` (`status`, `send`).
- `/www/luci-static/resources/view/homepanel/overview.js` — страница:
  - форма настроек (`form.Map` на `/etc/config/homepanel`): `enabled`
    (Flag), `server_url` (Value), `secret` (Value, скрытый), `interval`
    (Value, целое);
  - блок статуса (из ubus `homepanel.status`: время последней отправки,
    число клиентов, версия, текст последней ошибки);
  - кнопка «Отправить сейчас» (ubus `homepanel.send`).

Свой rpcd-скрипт не требуется: настройки — штатным UCI-RPC LuCI, статус и
отправка — через ubus-объект агента. Сброс кэша LuCI после установки:
`rm -f /tmp/luci-indexcache*` и `reload rpcd`.

## 8. Сервер (`homepanel-server`, Python 3 stdlib)

- `ThreadingHTTPServer` + `BaseHTTPRequestHandler`; привязка к локальному
  интерфейсу (за NPM); порт из конфига (по умолчанию 8787).
- Роли: (а) приём `/api/ingest`; (б) JSON-API `/api/*` для панели;
  (в) отдача статики панели.
- SQLite: одна общая БД, режим WAL, доступ через `threading.Lock`
  (или единственный писатель). `check_same_thread=False`.
- Фоновые задачи:
  - **тик истечения grace** (каждые ~15–30 с): устройства `home` без
    свежего `last_seen` → `away` + событие `left`;
  - **запись минут присутствия** (по границе минуты): строка в
    `minute_presence` для каждого «домашнего» устройства;
  - **роллап/очистка** (по расписанию/при старте): расчёт `daily_presence`,
    удаление `minute_presence` старше `retention.minuteDays`, `daily_presence`
    старше `retention.dailyDays`.
- Ошибки: JSON `{ "error": { "reason", "message" } }` + корректный HTTP-код;
  сервер не падает из-за ошибок в данных.

## 9. Модель данных (SQLite)

- **`devices`** — реестр: `mac` (PK, lower-case), `name`, `person` (строка),
  `kind` (phone/laptop/tv/iot/other), `trust` (own/guest/unknown),
  `hidden` (0/1), `notes`, `created_at`, `updated_at`.
- **`presence`** — текущее состояние: `mac` (PK), `state` (home/away),
  `last_seen`, `since`, `bss`, `band`, `signal`, `ip`, `hostname`, `updated_at`.
- **`events`** — переходы: `id` (PK autoincrement), `mac`,
  `type` (arrived/left), `ts`, `bss`, `band`, `ip`.
- **`minute_presence`** — `(mac, minute_ts)` PK; строка за каждую минуту
  онлайн (`INSERT OR IGNORE`).
- **`daily_presence`** — `(mac, day)` PK, `minutes`; дневной роллап.

Индексы: `events(ts)`, `events(mac, ts)`, `minute_presence(mac, minute_ts)`,
`presence(state)`.

## 10. Логика присутствия

- При каждом снимке всем клиентам из списка: `last_seen = now`, обновление
  `bss`/`band`/`signal`/`ip`/`hostname`.
- Устройство **дома**, если `now − last_seen ≤ grace` (по умолчанию 300 с).
- Переходы:
  - появление (было `away`/неизвестно, стало свежим) → событие `arrived`,
    `state = home`, `since = now`;
  - истечение grace (было `home`, `last_seen` устарел) → событие `left`,
    `state = away`.
- **Человек дома**, если дома хотя бы одно его не скрытое устройство.
- Неизвестные устройства (нет в `devices`) всё равно отслеживаются и
  показываются отдельным блоком для последующей разметки.
- Grace можно переопределять на конкретное устройство (поле в `devices`,
  будущая возможность — в v1 общий из конфига).

## 11. JSON API панели

| Метод | Путь | Параметры | Ответ |
|---|---|---|---|
| POST | `/api/ingest` | — (тело §5, секрет) | `{ ok, ts }` |
| GET | `/api/state` | — | люди, устройства, статус агента, время последнего снимка |
| GET | `/api/devices` | — | реестр + текущее присутствие |
| POST | `/api/devices` | `{ mac, name?, person?, kind?, trust?, hidden?, mergeInto? }` | обновлённая запись |
| GET | `/api/events` | `since?`, `limit?` | лента `arrived`/`left` |
| GET | `/api/stats` | `from`, `to`, `group=hour\|day\|week`, `mac?`/`person?` | агрегаты минут онлайн |
| GET | `/*` | — | статика панели |

- Кодировка UTF-8, JSON.
- `mergeInto` объединяет MAC-адреса (перенос `name`/`person`/`kind`/`trust`).

## 12. Веб-панель

Ванильный HTML/CSS/JS, без сборки; hash-роутинг; запросы к `/api/*`.

- `#/` — **Кто дома**: карточки по людям (дома/нет, с какого времени,
  устройство, диапазон/точка, сигнал), блок неопознанных, индикатор свежести
  данных. Авто-обновление **polling** ~10–15 с (минимальная правка DOM,
  без перерисовки всего экрана).
- `#/devices` — **Устройства**: таблица, правка `name`/`person`/`kind`/
  `trust`/`hidden`, объединение MAC, подсветка неопознанных.
- `#/history` — **История**: столбчатые графики часов онлайн по дням/неделям
  (свой SVG/CSS, без библиотек), выбор периода и человека.
- `#/settings` — **Настройки**: показ секрета и адреса для агента, подсказки
  по LuCI-странице на роутере, тумблеры уведомлений, сроки хранения.

Адаптивная вёрстка (телефон/десктоп). Стиль — тёмная тема, аккуратные
акценты (в духе `pi/opencode.html`).

## 13. Уведомления

- Браузерный `Notification` API. Работает в защищённом контексте — панель
  открывается по **HTTPS-домену Nginx Proxy Manager** (не по «сырому»
  `IP:port`, иначе уведомлений не будет).
- Разрешение запрашивается по кнопке-колокольчику (нужен жест пользователя).
- Триггеры: события `arrived`/`left` для выбранных людей/устройств. Панель
  при каждом опросе забирает `events` после последнего известного `id`
  (хранится в памяти/localStorage) и поднимает уведомления.
- При отказе в разрешении — мягкий откат на всплывашки внутри страницы.
- Web Push при закрытой вкладке — вне v1.

## 14. Конфигурация

**Сервер, `config.json`:**
```json
{
  "host": "0.0.0.0",
  "port": 8787,
  "secret": "CHANGE_ME",
  "graceSeconds": 300,
  "retention": { "minuteDays": 30, "dailyDays": 365 },
  "publicUrl": "https://homepanel.example.com"
}
```

**Роутер, `/etc/config/homepanel` (UCI):**
```uci
config homepanel 'main'
    option enabled '1'
    option server_url 'http://192.168.1.10:8787/api/ingest'
    option secret 'CHANGE_ME'
    option interval '30'
```

Секрет в `config.json` сервера и в UCI на роутере должны совпадать.

## 15. Деплой

**Сервер.**
- Запуск: `python3 server/server.py` (зависимостей нет).
- `server/systemd/homepanel.service`: `ExecStart=/usr/bin/python3 …/server.py`,
  `WorkingDirectory`, `Restart=on-failure`.
- Nginx Proxy Manager: прокси-хост на `http://<LAN-IP>:8787` — SSL-сертификат
  Let's Encrypt, при необходимости ограничение внешнего доступа по IP на
  стороне NPM. `/api/ingest` должен быть доступен с IP роутера.
- `README.md`: установка, конфиг, systemd, NPM, заметки по безопасности.

**Роутер.**
- `router/install.sh` раскладывает: `agent.uc`, `/etc/init.d/homepanel-agent`,
  UCI-умолчания `/etc/config/homepanel`, файлы LuCI (`menu.d`, `acl.d`,
  JS-вид); затем `/etc/init.d/homepanel-agent enable start`, `reload rpcd`,
  очистка `/tmp/luci-indexcache*`.
- **Персистентность:** при `sysupgrade` разделы `/usr` и `/www`
  перезаписываются, `/etc` сохраняется. Поэтому копия инсталлятора и файлов
  кладётся в персистентный `/etc/homepanel/`, а переустановка — одной
  командой. Упаковка в `.apk` — будущая итерация.

## 16. Тестирование (TDD)

- **Сервер** (`server/tests/`, `unittest`):
  - `/api/ingest`: проверка секрета (401), разбор тела, отклонение `schema > 1`;
  - автомат присутствия: `arrived`/`left`, истечение grace, идемпотентность
    повторных снимков;
  - агрегация: запись `minute_presence`, роллап `daily_presence`, `/api/stats`,
    очистка по retention;
  - реестр: CRUD `/api/devices`, объединение MAC (`mergeInto`), скрытие;
  - обработка ошибок и неизвестных путей.
- **Агент** (`router/tests/`):
  - режим `--once` на офлайн-фикстурах (`ubus` get_clients + `dhcp.leases`)
    → ожидаемый JSON-снимок;
  - чистые функции: разбор `dhcp.leases`, объединение клиентов по BSS.
- **Панель**: ручной чек-лист сценариев (§1) на десктопе и телефоне.

## 17. Ограничения и риски

- **Рандомизация MAC** (iOS/Android): устройство может приходить с разными
  MAC — полностью не решается; смягчаем сопоставлением по hostname и ручной
  разметкой.
- **WiFi-сон**: телефоны отваливаются при засыпании — гасится параметром grace.
- **Потеря событий при простое сервера**: поэтому «часы онлайн» считаем по
  `minute_presence`, а не по парам событий.
- **Форма вывода `hostapd.*.get_clients`** может отличаться по версии —
  зафиксируем живым примером в начале реализации.
- **Раскладка LuCI-приложения без buildroot** чувствительна к версии
  (пути `menu.d`/`acl.d`, формат JS-вида) — проверяем на целевой 25.12.
- **POST у busybox `wget`** (`--post-file`) — при отсутствии используем
  `uclient-fetch`.
- **Уведомления только по HTTPS-домену NPM**, не по `IP:port`.

## 18. Открытые вопросы

Нет — ключевые решения зафиксированы: назначение (v1 — WiFi-присутствие),
источник данных (push-агент на роутере), интерфейс роутера (ucode-агент +
настройки в LuCI), стек (ucode на роутере, Python stdlib + SQLite на сервере,
ванильный JS без сборки), история (SQLite + графики), уведомления (браузерные
через HTTPS NPM), доступ (локально без логина; внешне — NPM/фаервол), TLS
(Nginx Proxy Manager).
